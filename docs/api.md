# HTTP API reference

The API is `service/api.py` (FastAPI, port 8000). It hosts the LangGraph agent and is the only thing a client
talks to. The UI, the demo scripts and the evals are all clients of it. How it reaches MCP and A2A is in
[API_MCP_A2A_interaction.md](API_MCP_A2A_interaction.md); the UI is in [ui.md](ui.md).

```bash
scripts/start_all.sh                        # MCP + TerraMind + API + UI
# or only the API (the MCP server must already be running, or the API will not start):
uvicorn service.api:app --port 8000
```

Interactive docs generated by FastAPI: `http://127.0.0.1:8000/docs`.

## Endpoints at a glance

| Method and path | Purpose | Success | Errors |
|---|---|---|---|
| `POST /chat` | One conversation turn | 200 `{session_id, reply, trace, turn}` | 422 bad body; 500 unhandled failure |
| `GET /health` | Liveness, model, bound tools | 200 | none |
| `GET /tools` | Each bound tool's description and parameter text | 200 | none |
| `GET /sessions/{id}` | Stored conversation (tool calls and results included) | 200 | 404 unknown session |
| `GET /sessions/{id}/node_runs` | Node-level trace of every turn | 200 | none: unknown id gives `turns: []` |
| `GET /sessions/{id}/export` | One JSON file with the whole session | 200 | 404 unknown session |

## `POST /chat`

Request:

```json
{"session_id": "demo-1", "message": "What Sentinel-2 imagery is available for Hyderabad in January 2024 with less than 10% cloud cover?"}
```

- `session_id` is any string you choose. The first message with a new id starts a session; later messages with the
  same id continue it ("the same period", "the second one" resolve from the stored state). The id is the LangGraph
  `thread_id` in the SQLite checkpointer, so a session survives an API restart.
- `message` is the user's text. It is not validated: an empty or blank message is passed to the model.

```bash
curl -s http://127.0.0.1:8000/chat \
  -H 'content-type: application/json' \
  -d '{"session_id":"demo-1","message":"Cloud-free Sentinel-2 imagery of Hyderabad in January 2024?"}'
```

Response (shape; `reply` and the later trace entries are shortened):

```json
{
  "session_id": "demo-1",
  "reply": "There are **7 Sentinel-2 L2A scenes** covering Hyderabad ... (search_stac_items)\n\n| Scene ID | Date | Cloud Cover | ...",
  "turn": 1,
  "trace": [
    {"timestamp": 1791125934.55, "session_id": "demo-1", "step": "tool_call", "tool_name": "geocode_location",
     "args": {"query": "Hyderabad"}, "duration_ms": 71.2, "error": null, "final_answer": null},
    {"timestamp": 1791125937.99, "session_id": "demo-1", "step": "tool_call", "tool_name": "search_stac_items",
     "args": {"bbox": [78.2387, 17.2916, 78.6223, 17.5608], "collections": ["sentinel-2-l2a"],
              "start_date": "2024-01-01", "end_date": "2024-01-31", "max_cloud_cover": 10, "limit": 50},
     "duration_ms": 2396.8, "error": null, "final_answer": null},
    {"timestamp": 1791125939.56, "session_id": "demo-1", "step": "verify", "tool_name": null,
     "args": {"issues": [], "rewritten": false, "caveat": false}, "duration_ms": null, "error": null, "final_answer": null},
    {"timestamp": 1791125939.56, "session_id": "demo-1", "step": "agent_turn", "tool_name": null,
     "args": null, "duration_ms": 5681.4, "error": null, "final_answer": "There are **7 Sentinel-2 L2A scenes** ..."}
  ]
}
```

(The trace entries above are from `demo/demo_trace.jsonl`.)

### The `trace` field

One entry per step of this request, in order. The same entries are appended to `logs/traces.jsonl`.

| Field | Meaning |
|---|---|
| `step` | `tool_call` (one per tool invocation, MCP or A2A), `verify` (the groundedness verdict), `context_summary` (only on a turn where older turns were folded into the summary), `agent_turn` (once, last: total latency and the final reply) |
| `tool_name`, `args` | For `tool_call`: the tool and its arguments. For `verify` and `context_summary`, `args` holds the verdict or the summary settings |
| `duration_ms` | Time taken (`tool_call`, `agent_turn`) |
| `error` | Error text, or `null`. For `verify` it is set only when the reply was left with a `⚠️ Could not verify…` caveat |
| `final_answer` | Set on `agent_turn` (the reply), and on `context_summary` (the new summary) |

`turn` is the 1-based turn number in the session. Use it to pick this turn out of `GET /sessions/{id}/node_runs`.

## `GET /health`

```bash
curl -s http://127.0.0.1:8000/health
# {"status":"ok","model":"<provider:model>","tools":["geocode_location","list_stac_collections","search_stac_items","get_stac_item","get_weather","embed_scene","compare_embeddings","rank_similar"]}
```

`tools` lists every tool bound to the agent. If the TerraMind agent was not running when the API started, the three
TerraMind tools are missing from this list. The evals read this list and skip the `a2a` cases when they are absent.

## `GET /tools`

Returns `{"tools": [{"name", "description", "text"}, ...]}`: what each tool says about itself. `text` is the
description plus parameter descriptions. The verifier treats whole numbers in it (for example "16 days ahead") as
supported facts about the tool's limits, and the evals use the same text.

## `GET /sessions/{id}`

```bash
curl -s http://127.0.0.1:8000/sessions/demo-1
```

```json
{
  "session_id": "demo-1",
  "messages": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "", "tool_calls": [{"id": "...", "name": "geocode_location", "args": {"query": "Hyderabad"}}]},
    {"role": "tool", "name": "geocode_location", "tool_call_id": "...", "content": "{...raw tool result...}"},
    {"role": "assistant", "content": "There are 7 scenes ...", "tool_calls": []}
  ],
  "summary": null,
  "summarized_turns": 0
}
```

This is the **stored** history. Tool results here are raw, not the compacted form the model sees on later turns.
`summary` and `summarized_turns` show the rolling summary once it has fired. 404 if the session has no messages.

## `GET /sessions/{id}/node_runs`

`{"session_id", "turns": [{"turn": 1, "node_runs": [...]}, ...]}`. Each node run records the node name, its model
calls (full prompt, tokens, latency), and its tool calls. This is what draws the UI's graph trace. Read from
`logs/node_runs/<session_id>.jsonl`. An unknown id returns an empty `turns` list, not a 404.

## `GET /sessions/{id}/export`

One JSON document with everything about a session:

| Key | Content |
|---|---|
| `messages`, `summary`, `summarized_turns` | the stored conversation, as in `GET /sessions/{id}` |
| `node_runs` | the node-level trace of every turn |
| `trace` | this session's lines from `logs/traces.jsonl` |
| `terramind_log` | this session's lines from `logs/terramind.jsonl` (the A2A agent's own log) |
| `embeddings` | metadata of the embeddings this session created |
| `model`, `exported_at` | which model ran, and when it was exported |

```bash
python scripts/export_session.py demo-1          # writes it to a file
curl -s http://127.0.0.1:8000/sessions/demo-1/export > session-demo-1.json
```

The UI can replay such a file read-only (see [ui.md](ui.md)). 404 if the session has no messages.

## Error behaviour

What the client sees, by failure:

| Failure | What happens | Client sees |
|---|---|---|
| A tool fails (bad date, unknown id, upstream API down) | The tools node catches it and returns `Tool error: ...` to the model. The model explains it. The API stays up | **200**, a reply that says what was attempted and that it failed. The `trace` has a `tool_call` entry with `error` set |
| A tool keeps failing | The loop guard stops the turn after `EVE_MAX_TOOL_CALLS` (default 10) calls | **200**, a plain message saying it stopped, with the last error |
| The reply has a value the tools never returned | The verifier asks for one rewrite, then adds a caveat | **200**, with `⚠️ Could not verify…` at the end if the rewrite did not fix it; `verify` step in `trace` |
| TerraMind agent unreachable at start-up | Warning in the log; the API starts without its three tools | `GET /health` lacks them |
| TerraMind agent fails during a call | Raised as `TerraMind agent: ...` inside the tool, so it is handled like any tool error | **200** with an explanation |
| MCP server unreachable at start-up | The API **does not start** (the MCP connection is required) | connection refused on port 8000 |
| Request body missing `session_id` or `message`, or not JSON | FastAPI validation | **422** with the field list |
| Unknown session on `GET /sessions/{id}` or `/export` | | **404** `{"detail": "no session 'x'"}` |
| An unhandled failure outside a tool (for example the model provider is down or the key is rejected) | Not caught in `POST /chat` | **500** `Internal Server Error`; the traceback is in `logs/api.log` |
| Missing `GROQ_API_KEY` with the default provider | The API refuses to start | process exits with `GROQ_API_KEY not set` |

The first three rows are the assignment's error path: the demo's turn 3 (`get_weather` with `start_date='2024-02-30'`)
shows it end to end in [`demo/demo_transcript.md`](../demo/demo_transcript.md).

There is no authentication, rate limit or request-size limit. A turn that embeds scenes can take over a minute
(about 30 seconds per scene), so use a long client timeout (the UI uses 600 s).

## Finding one request in the logs

Everything is keyed by the session id:

```bash
grep demo-1 logs/api.log                                  # API log lines carry [session_id]
jq 'select(.session_id=="demo-1")' logs/traces.jsonl      # the trace entries
jq 'select(.session_id=="demo-1")' logs/terramind.jsonl   # the TerraMind agent's calls
cat logs/node_runs/demo-1.jsonl                           # node-level trace per turn
```

## Settings

Environment variables (a `.env` file is read at start-up; `.env.example` lists them):

| Variable | Default | Effect |
|---|---|---|
| `GROQ_API_KEY` | none | required with the default provider |
| `EVE_LLM_PROVIDER`, `EVE_MODEL`, `EVE_LLM_BASE_URL` | `groq` | which model serves the agent |
| `EVE_SUMMARY_TOKEN_BUDGET` | 3000 | fold old turns into a summary when the prompt would exceed this (0 = fixed schedule) |
| `EVE_KEEP_RECENT_TURNS` | 2 | turns kept verbatim |
| `EVE_MAX_TOOL_CALLS` | 10 | tool calls allowed per turn |
| `CHECKPOINT_DB_PATH` | `data/checkpoints.sqlite` | where sessions are stored |
| `MCP_SERVER_URL` | `http://127.0.0.1:8765/mcp` | where the API finds the MCP server |
| `TERRAMIND_A2A_URL` | `http://127.0.0.1:8767` | where the API finds the TerraMind agent |
| `TERRAMIND_A2A_TIMEOUT` | 180 | seconds to wait for one TerraMind call |
